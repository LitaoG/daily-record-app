# 月统计改版契约

最后更新：2026-08-02

## 为什么改

主页日历负责回答“哪一天发生了什么”。如果统计页的“月”周期再次绘制同一套日期格，用户看不到额外的月度信息，页面也会被 31 个状态单元占满。因此月统计不再复刻日历，而是回答“这个月的节奏如何”。

## 当前交付

月统计保留原来的月份导航、总次数和发生天数摘要，下面改为一个月内周聚合卡：

- 按当前月份的周一至周日边界生成 5 或 6 个周桶；周桶只统计落在所选月份内的日期，不把相邻月份的数据带入。
- 每个周桶展示次数柱、周序号和发生天数；次数为 0 时柱高严格为 0，未填写与未来周不绘制柱高并保留不同语义。
- 卡片摘要展示活跃周数和峰值周；峰值并列时完整展示并列周。
- 当前浏览月份改变时，周桶、峰值和活跃周数整体重新计算，不沿用上一月份的结果。
- 手冲和做爱仍通过同一泛型统计函数计算，但传入的 `DailyCountEntry` 只来自当前模块，不能交叉混合。

## 明确不做

- 不改变主页日历日期格、周统计、年度统计、全部历史、登录、同步或数据库。
- 不新增时间、感受、备注、目标、提醒或其他统计维度。
- 不引入图表依赖；月内 5/6 个柱使用现有 Compose 绘制能力。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 空月 | 5/6 个周桶均为空，峰值显示空状态，柱高为 0 |
| 明确 0 次 | 所属周显示 `0 次`、0 天，柱高为 0，但该周不是未填写 |
| 正次数 | 次数按月内周桶汇总，发生天数按次数大于 0 的日期计算 |
| 未来周 | 次数和天数为空，柱高为 0，不制造预测 |
| 五周月/六周月 | 周桶数量和起止日期由 `YearMonth` 重新生成 |
| 闰年二月 | 只生成当月真实日期所在的周桶，不因 29 天复制或遗漏数据 |
| 切换月份 | 旧月的总量、周桶、峰值和活跃周不残留 |
| 双模块 | 当前模块的周桶不读取另一个模块的记录 |

对应纯模型：`StatisticsModels.kt`；对应展示：`StatisticsStage4Components.kt`；对应入口：`StatisticsScreen.kt`。本变更使用 `docs/TESTING.md` 的增量规则：先运行统计模型测试、Debug/AndroidTest 编译和 Lint；不重复已经通过且未受影响的 Firebase 规则与整套设备回归。
