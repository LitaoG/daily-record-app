## 1. 总目标

消除账号删除、记录清除、本机记录接管和统计状态展示中的真实风险，补齐与当前产品契约相对应的自动化测试和文档。

本轮不新增功能，不重新设计 UI，不改变统计口径，不扩大记录类型，不更换 Firebase，不加入 SQLCipher，也不进行破坏性数据库迁移。修复必须保持以下产品约束：

- 本机优先、无强制登录；离线记录可继续使用。
- 自慰与做爱使用独立领域模型、表、同步边界和主题状态。
- `UNSET`、`MISSED`/明确 0 次、正次数和未来日期必须保持可区分。
- 设备系统时间不能决定跨设备冲突胜负。
- 删除账号必须同时处理云端数据、待同步任务和本地 owner 数据。

## 2. 审查结论

### 必须修复（下一次发布前）

| 编号 | 结论 | 事实与风险 |
|---|---|---|
| S1 | 确认，隐私风险 | 删除流程已有 `deletionInProgress`，能停止前台同步，但 `onLocalChange` 仍可调度 WorkManager，Worker 也没有删除状态闸门。删除云端文档后，竞态上传可能重新写入孤儿私密文档。 |
| M2 | 确认，并发风险 | `markDeleted` 只按 owner 和 id 更新，没有校验 `updated_at`。清除记录与保存编辑交错时，旧清除请求可能删除较新的编辑。 |
| M5 | 确认，数据一致性风险 | 本机记录接管账号时使用 `updatedAt` 判断本地与账号缓存的新旧，和 ADR-010“设备时间不能决定胜负”冲突。跨设备时钟偏差可能静默丢弃本机编辑。 |
| S2 | 确认，统计解释错误 | 周环图把“未填写”与“0 次”绘制为不同状态，但图例把“0 次”标成未填写颜色，且缺少“未填写”条目。用户会按图例误读数据。 |
| M3 | 确认，删除流程不可恢复 | Firebase 账号删除发生在本地 owner 清理之前。本地清理失败时界面可能显示失败，但账号已经不存在，重试路径不成立；旧本地数据可能残留。报告中“同邮箱新账号复活旧数据”不是准确表述，Firebase UID 仍然隔离。 |

### 建议同一轮加固

| 编号 | 结论 | 处理建议 |
|---|---|---|
| M4 | 代码路径成立，严重程度需集成验证 | 实时监听重试列表不包含 `UNAUTHENTICATED`，监听可能终止而不重新订阅。增加认证恢复和监听重建测试，并补充明确的重订阅策略。 |
| M7 | 确认，低频边界问题 | 最早支持日期为 1970-01-01 时，周起始计算会显示 1969-12-29 至 31，且上一周不可导航。应裁剪显示范围或调整首周锚点。 |
| M5b | 确认，云端删除后的自愈缺口 | 本地 `remoteRevision > 0` 的待同步记录遇到云端同日文档消失时会抛出数据错误；Worker 重试 5 次后放弃，没有明确的重建或冲突收敛路径。 |
| Sync isolation | 确认，模块级韧性不足 | `CombinedSyncCoordinator` 顺序执行模块；自慰同步抛异常时做爱同步不会执行。失败模块的数据仍留在本地，但应改为逐模块聚合结果，避免互相阻塞。 |
| A11y | 确认，辅助功能一致性问题 | 视觉文案显示“9 次以上”，TalkBack 语义可能读精确次数；`height(44.dp).padding(2.dp)` 后才执行 `clickable`，实际日期格点击区域约 40dp，低于 48dp 建议值。 |

## 4. 不作为当前修复项

以下内容本轮不建立代码修复任务，避免把低风险代码味道误当成发布阻塞：

- 5 秒限制的准确边界待确认：Worker 路径不受 5 秒限制；但 `AccountSyncManager` 内自动同步（网络恢复 `:91`、快照冲刷 `:70`）仍会进入 `performSyncAttempt` 的 5 秒超时。是否接受该行为由产品确认，本轮不直接修改代码。
- `5→6→5` 草稿覆盖属于编辑策略选择。当前 `hasChanges` 表示最终值是否改变；只有产品要求“触碰过就保护草稿”时才增加 dirty 标记。
- `runCatching` 对取消异常的处理属于低风险清理项，不阻塞本轮。
- `moveOwner`、`rankedMonthCount` 等死代码必须先完成全局调用点确认，不能依据名称直接删除。
- 邮箱标准化重复实现、Goal 颜色与运行时颜色不同，属于低优先级重构或文档漂移。
- 当前没有证据表明 UI 文案普遍散落；主要 UI 文案已经集中在 `AppCopy`。优先修复迁移 SQL 的机器键问题。

## 5. 分阶段执行计划

### Stage A：隐私与并发安全

对应：S1、M2、M3、M5、M5b。

要求：

1. 删除账号进入不可竞态状态后，任何本地变更回调不得新建同步任务。
2. Worker 在开始远端读写前再次检查删除闸门；删除期间已存在的任务必须安全退出。
3. 账号删除失败必须明确区分“认证未删除”“云端未删除”“本地清理待修复”，不能把已删除账号报告为可重试的普通失败。
4. `markDeleted` 使用 `updated_at` 乐观并发条件；影响行数为 0 时不得覆盖新编辑。
5. 本机接管使用 `remoteRevision` 或显式冲突策略，不能使用设备时钟作为跨设备胜负依据。
6. 云端同日文档消失时，必须按明确策略收敛为冲突、墓碑或新的远端 revision，不能让 pending 记录在重试耗尽后永久停留在数据失败。

### Stage B：统计与同步一致性

对应：S2、M4、M7、Sync isolation、A11y。

要求：

1. 周环图图例必须同时表达“未填写”“明确 0 次”“正次数区间”“未来”，并与绘制颜色一一对应。
2. 认证恢复后实时监听必须重新订阅，且不能重复订阅或泄漏旧监听。
3. 最早支持日期的周视图不得显示 1970 年以前的日期。
4. 一个模块同步失败不能阻断另一个模块；结果需逐模块记录。
5. TalkBack 文案与视觉统计必须使用同一套状态分桶；日期格可点击区域至少 48dp。

### Stage C：迁移、测试与文档

对应：M1、M8、M9 以及低风险清理。

要求：

1. 迁移只使用稳定机器键；非目标活动必须带有 `quantity > 0` 的正例，才能证明 `WHERE` 过滤生效。
2. 增加 Q1/Q2 具有不同值的季度切分测试，不能只断言季度总和恒等式。
3. 增加密码重置“发送中” UI 测试，验证按钮、输入框和关闭动作被锁定，完成或失败后恢复。
4. 增加进程被杀后 WorkManager 待同步任务恢复的测试。
5. 增加跨年周、最早日期、时区切换和认证恢复测试。
6. 更新 `DEVELOPMENT.md`、Goal 索引和审计记录，不改变历史审计材料。

## 6. 验收标准

### 数据与隐私

- 删除账号竞态测试中，删除完成后不会产生新的上传，也不会留下可访问的孤儿文档。
- 并发保存与清除测试不会删除较新的编辑。
- 本机接管在设备时钟前后偏差场景下不会静默丢失记录，并且结果可解释。
- 删除失败状态可恢复，不会出现“账号已删除但界面要求再次删除”的死路。
- 云端记录消失后，本机待同步记录不会在重试耗尽后永久停留在数据失败。

### 统计与交互

- 周环图四类状态和图例颜色严格对应。
- 首个支持周不出现 1969 年日期。
- 认证恢复后监听只存在一个有效订阅。
- 迁移过滤、季度切分和密码重置发送中锁定都有独立回归测试。
- 自慰失败时做爱模块仍能独立同步或明确记录失败。
- TalkBack、视觉文案和点击热区符合同一状态契约。

### 工程与发布

- 受影响单元测试、Android Lint、AndroidTest 编译和相关设备测试通过。
- Firestore 规则和 Room 迁移测试不回归。
- `git diff --check`、Markdown 链接检查、敏感信息扫描通过。
- 不增加破坏性数据库迁移，不修改无关 UI 和产品功能。
