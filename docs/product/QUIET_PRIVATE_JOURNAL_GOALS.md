## 2. 总目标

在不改变现有双模块数据、统计、登录或同步语义的前提下，统一改版以下三个核心页面：

- 日历页：使用轻微圆角方形日期热力单元，减少汉字和常驻边框。
- 日期记录页：点击日历日期后进入；次数是唯一主焦点，保存是唯一主操作。
- 统计页：总次数是唯一主指标，发生天数和记录日均为辅助事实；月统计使用按周聚合次数柱和月内洞察，年统计使用 12 个月柱状分析。

产品仍只记录两个固定且独立的模块：

- 手冲。
- 做爱。

本轮不新增时间、感受、备注、伴侣、地点、时长、图片、医疗信息、目标、连续天数、提醒或其他记录类型。

## 3. 已确认的视觉基线

### 3.1 共用视觉语言

- Canvas 使用接近白色的暖中性色，不使用明显发黄的纸张纹理。
- 正文使用石墨色；减少纯黑、大面积粗体、阴影、厚描边和卡片套卡片。
- 两个模块共用页面结构、排版、间距、圆角、底部导航、错误色与成功色。
- 模块色只用于当前模块身份、热力强度、焦点、主按钮和选中状态；不能成为唯一的状态说明。
- 以下颜色是已确认的实现起点。允许为 WCAG 对比度做小幅明度调整，但不得更换已确认的紫色/深红色相方向；调整必须记录在阶段 1 PR 中。

| 角色 | 基线值 |
|---|---|
| Canvas | `#FAF8F3` |
| Surface | `#FFFEFB` |
| Primary text | `#2D2926` |
| Subtle line | `#D8D0C6` |
| 手冲主色 | `#72517C` |
| 手冲深色 | `#4B3354` |
| 做爱主色 | `#8D3E45` |
| 做爱深色 | `#5F272C` |

### 3.2 模块切换器

- 单层外框严格二等分；左右模块各占完整宽度的一半和完整高度。
- 选中颜色必须覆盖对应半区直至外框边界，不允许恢复内部小胶囊。
- 文字与图标居中，选中视觉范围、语义范围和点击范围一致。
- 手冲使用紫色系和飞机符号；做爱使用深红色系和非露骨双环符号。

### 3.3 日历页

- 日期使用统一的方形或轻微圆角方形数据单元，不使用圆形日期点。
- 过去未填写只显示日期并使用浅中性底，不显示“未填”汉字；TalkBack 仍明确“未填写”。
- 明确 0 与未填写不同，使用空心标记或独立边框；保存 0 不等于清除。
- 1、2、3+ 使用当前模块同色系整格背景逐级加深，同时保留精确次数或稳定标记。
- 今天保留“今”或今天边界；未填写的今天仍保持浅色。
- 未来日期使用区别于过去未填写的独立禁用浅色，只淡化和禁用，不在日期格内显示“未来”汉字。
- 日历首页月摘要只显示“本月总次数 · 发生天数”，记录日均留在统计页。
- 短月份在底部导航上方使用轻分隔、点击提示和集中四态图例收尾；不增加说明卡或新功能。
- 点击日期进入日期记录页；日历格内不提供加减控件。
- 月份切换、年月快速跳转、浏览日期和模块切换行为保持不变。

### 3.4 日期记录页

- 从日历日期进入，不成为第三个底部导航入口。
- 顶部明确日期和当前模块；次数数字是唯一主焦点。
- `-1`、`+1` 点击目标至少 48dp；次数下限仍为 0。
- 保存是唯一主按钮；清除是次级文字操作，已有确认逻辑保持不变。
- 只显示一套当前记录状态和一行低权重月度上下文，不堆叠解释卡。
- 不显示时间、感受、文本框或其他尚未立项字段。

### 3.5 统计页

- 周、月、年、全部继续使用同一浏览日期和现有统计口径。
- 总次数是唯一主指标；发生天数和记录日均为辅助事实，不使用三张等权 KPI 卡。
- 0 次图形为真正零高度；未填写不伪装成 0；未来不预测。
- 月统计使用当前月的 5/6 个周聚合柱，展示次数、发生天数、活跃周数和峰值周；不再重复日历页的真实日期网格。周桶由当前 `YearMonth` 的真实 `LocalDate` 生成，与日历页共用未填写、明确 0 和未来语义。
- 年统计不使用 53×7 的逐日热力图，避免手机端过密；主图固定为 12 个月次数柱状图。
- 年统计另外提供季度次数占比圆环、月均次数、最高月份和最低月份；柱状图与折线图信息重复，不同时堆叠。
- 当前年份的未来月份为空，进行中的当前月可以显示但不进入最高/最低排名；过去年份使用全部 12 个月。
- 最高/最低月份只在至少存在一条已保存记录的完整月份中计算，未填写月份不伪装成 0；明确保存 0 的月份可以合法成为最低月份。
- 最高/最低出现并列时完整列出并列月份；没有合格月份时显示明确空状态。
- 季度圆环只计算正次数占比，总次数为 0 时显示空状态，不制造占比。
- 手冲和做爱分别读取自己的逐日数据，绝不混合。

## 6. 各阶段范围

### Stage 0：仓库清理与执行基线

只处理设计资产、文档、Issues、标签、分支、PR 和 Git 同步：

- 公共 `main`、本地 `main` 与工作分支来源一致。
- 保留 Git 历史、Release 和历史审计；删除无引用的临时执行状态，过时设计明确标为历史。
- 当前事实文档不得把双模块产品描述为“仅手冲”。
- 新设计图、本文、总 Goal 和全部子 Goal 相互链接。
- 运行文档链接、敏感信息和 Git 完整性检查。
- 本阶段不修改 Android 运行时代码，不运行与纯文档/图片无关的完整 Android 套件。

### Stage 1：设计 Token 与共享外壳

- 建立 Canvas、Surface、文字、分隔线、成功、危险、手冲紫色与做爱深红色职责。
- 为未填写、0、1、2、3+、焦点和禁用状态建立可访问色阶。
- 统一文字、等宽数字、间距、圆角、描边、阴影和图标规范。
- 实现严格二等分、单层、完整半区点击的模块切换器。
- 统一周期切换、底部导航和页面基础边距。
- 不改变记录、统计、登录、同步、Room 或 Firestore 逻辑。

实现证据：[2026-07-30 Stage 1 定向验收](audit/2026-07-30-ui-v2-stage1/README.md)。用户已验收，Stage 1 关闭。

- 模块切换不得重置月份或日期。
- 完成正常字号、200% 字体、390×844、窄屏和 TalkBack 证据。

## 7. 测试纪律

严格遵循 [`TESTING.md`](../TESTING.md)：

- 修改中只运行覆盖当前影响面的最小编译、单元、Compose、截图或语义检查。

- 纯文档、Issues 和设计图片只运行文档完整性、链接、敏感信息与 Git 检查。

## 8. GitHub 与暂停规则

- 日常分支、提交、PR、CI、审查和合并全部在公共 [`LitaoG/daily-record-app`](https://github.com/LitaoG/daily-record-app)完成。
- 每个阶段从最新公共 `main` 建立一个短生命周期 `agent/<description>` 分支。
- 不强推、不改写共享历史、不删除 Release/tag/已关闭 Issue/历史审计。
- 阶段完成并等待用户验收时，不提前开始下一阶段代码。
- 私有恢复仓库不是日常开发源；仅在完整小版本后同步。
