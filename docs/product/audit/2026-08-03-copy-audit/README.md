# 2026-08-03 应用内中文文案审查

## 目标

只保留帮助用户完成操作或理解记录状态所必需的文字。文案要短、直白、无重复；同一状态在日历、统计、同步和账号页面使用同一说法。

## 本轮结论

- “记录起点”和“首次记录”表达同一件事。全部历史页只保留顶部的年月范围，不再额外显示首次记录卡片。
- 年度折线图不再显示“只展示已发生数据，不预测未来趋势”一类用户已经能从图表读懂的说明。
- 月统计不再显示与副标题重复的单日极值提示。
- “次数构成”统一为“次数分布”；“3+次”统一为“3 次以上”；统计中的 0 次明确写成“0 次”。
- 登录、同步和删除失败均说明下一步动作，并明确“记录仍在本机”，避免把网络问题写成邮箱或密码错误。
- 日历图例用“未填写 / 未来 / 0 次 / 已记录”区分四种状态；TalkBack 仍提供完整句子。
- 时间跳转按钮按粒度分别写成“跳转到此日 / 此月 / 此年”。
- 2026-08-04 全仓生产源码审查确认：中文业务文案只保留在 `AppCopy.kt`；Android 系统应用名保留在 `res/values/strings.xml`，Room 历史迁移通过 `AppCopy.RecordModule.handBrewLabel` 生成兼容查询，不再在数据库代码中重复写中文。

## 约束

- 所有运行时页面文字集中在 `AppCopy.kt`；Composable 不自行拼接中文句子，应用商店/系统使用的应用名仍由资源文件维护。
- 本轮不改变记录、同步、统计计算或数据库规则。
- 历史审计材料保留原文，避免改写过去的验证证据；当前事实文档同步使用新术语。

## 验证清单

- 静态搜索确认运行时代码不再出现“记录起点”“明确没冲”“登录同步”“次数构成”等过时表述。
- `AppCopyTest` 覆盖日期范围、0 次语义、同步入口、次数分布和年度平均值。
- 日历、统计、账号与删除相关 UI 测试的期望文字与统一文案资源保持一致。
- 编译、单元测试、Lint、文档链接检查和 `git diff --check` 在提交前执行。
- `scripts/copy-integrity.test.mjs` 防止新的中文字符串落入生产 Kotlin、Java 或 XML；测试断言、数据库夹具和历史审计文档不属于运行时文案范围。
