# 局部一致性、扩展边界与安全加固

日期：2026-07-28

设备：Android 14 API 34 模拟器，1080 × 2280

范围：明显不协调的 UI、登录返回逻辑、多记录模块公共边界、账号删除容错和传输安全

## 范围约束

本轮不重新设计整体视觉语言，不调整既有排版尺度、配色体系或信息架构。只处理能够明确证明的问题：

- 手冲与做爱选择器的图标笔画和未选中颜色不一致。
- 统计页在模块选择器下方重复展示同一个模块标签。
- 从本机日历打开登录页后，系统返回键不能回到原日历。
- 通用组件和诊断标题仍被命名为手冲，未来新增模块会继续扩大错误耦合。
- 账号级同步与删除聚合器写死两个构造参数，第三个模块需要再次复制组合逻辑。
- Release 构建没有显式拒绝明文网络。

## 已验证结果

1. 从本机日历点击“登录同步”进入登录页，系统返回键恢复原日历；随后强制停止并冷启动，仍进入本机日历。
2. 模块选择器使用一致的图标层级；未选中模块统一使用中性深色，选中模块使用白色。
3. 统计页只保留选择器作为模块作用域来源，不再显示重复模块胶囊。
4. 显式保存 0 次后，日历语义为“明确记录 0 次”；清除后才恢复未填写。
5. 清除确认继续使用项目自有弹窗，不回退到系统默认 `AlertDialog`。
6. 诊断标题为 `Private Calendar diagnostics`，后台同步 Worker/Scheduler 也使用通用命名，不再把双模块应用写成 Hand Brew Calendar。
7. 连续五次冷启动为 2516–3259 ms，Crash Buffer 和应用 FATAL/ANR 检索均为空。
8. 2026-07-29 根据真机反馈把模块选择器改为单层分段控件：唯一的外层大圆角矩形由中线严格分成两个完整半区，删除内层胶囊、内缩留白和单独圆角；选中底色与点击范围都从外框边缘覆盖到中线，外侧圆角只由唯一外框裁剪。图标与文字组合居中，图标由 20 dp 放大至 24 dp，文字由 12 sp 放大至 16 sp。Android 边界测试和左右选中态截图回归均通过。

## 代码与安全结果

- `DailyCountRecord`、`DailyCountRecordRepository<T>` 和通用模块控制器只共享日期次数记录的最小契约；手冲与做爱仍保留独立实体、表、Repository、远端字段和 Firestore 集合。
- 同步、云端账号删除和本机删除聚合器改为非空模块列表，测试使用第三个假模块证明扩展不依赖二元分支。
- 多模块永久删除会尝试全部模块；首个异常作为主异常，其余异常保留为 suppressed，不静默跳过后续模块。
- Release Manifest 设置 `usesCleartextTraffic=false`；Debug 只为 Firebase Emulator Suite 覆盖为 true。
- 登录页不再宣称“安全合并”；实际边界由 Firebase Authentication、Firestore Rules、TLS、Android 沙箱和关闭系统备份共同提供。

## 已知边界

- 整体 UI 视觉重构不属于本轮，后续设计工作不得把本轮业务和安全规则当作可随意重解释的视觉文案。
- Room 当前没有应用层端到端加密，依赖 Android 沙箱、系统文件级加密和设备锁。引入 SQLCipher 前必须先设计密钥恢复和无损迁移。
- Firebase 云功能在中国大陆普通网络可能不可达；本机记录、日历和统计不依赖 Firebase。
