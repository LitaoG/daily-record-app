# 同步与隐私

最后复核：2026-08-09

应用坚持本地优先：未登录也能完整记录、查看日历和统计；登录只用于跨设备同步与恢复。所有界面数据来自设备内 Room，网络失败不会阻塞保存。

## 账号

- 仅提供邮箱和密码注册/登录，普通登录不使用短信或验证码。
- Firebase UID 是账号所有权边界；本机 Room 也按 UID 隔离缓存。
- 密码由 Firebase Authentication 处理，应用和 Room 不保存明文密码。
- 忘记密码使用 Firebase Authentication 向输入邮箱发送重置链接；应用不会读取、生成或保存新密码。
- 重置请求对已注册和未注册邮箱显示相同成功提示，避免通过界面枚举账号；断网、限频与额度错误只显示可执行的净化提示。
- 登录时，`__local__` 本机记录会合并到这次登录的账号；界面在操作前明确提示这一点。
- 用户明确选择本机模式后会跨冷启动保留该选择；点击顶部“登录并同步”只临时打开登录页，按系统返回键或登录页的本机入口会回到原日历。只有认证成功后才关闭本机模式偏好，避免登录中断或进程被系统回收后把用户困在登录页。
- 本机模式不初始化 Firebase，不需要 VPN（梯子）；登录、注册、密码重置与云同步需要可访问 Firebase，界面会提示在当前网络环境下开启。

## 云端数据

Firestore 使用两个独立路径：

- `/users/{uid}/handBrewRecords/{YYYY-MM-DD}`
- `/users/{uid}/sexRecords/{YYYY-MM-DD}`

手冲文档字段为 `brewCount`，做爱文档字段为 `sexCount`；其余包括稳定 ID、本地日期、创建/修改时间、删除墓碑、修订号、schema 版本、服务器更新时间和可选的模块专用 `details` 数组。详情只包含用户主动填写的逐次开始/结束时间与最多 100 个可见字符的感受；不保存伴侣、地点、姿势、位置、联系人、健康数据、额外备注、图片或设备标识。

生产数据库位于 `asia-east1`，以生产模式创建。安全规则要求：

- 必须已登录且 UID 与路径一致。
- 字段必须完全匹配白名单，次数非负且日期与文档 ID 一致。
- `details` 必须是当前模块的数组，条目数不能超过对应次数；客户端与远端解析器校验时间精度、时间顺序和感受的 100 个可见字符上限。
- ID、本地日期和创建时间在更新后不可改变。
- 修订号每次只增加 1；普通记录清除仍写墓碑。只有已登录本人执行永久账号删除时，规则允许物理删除自己路径下的文档。

生产构建通过 Manifest 禁止明文网络流量，Firebase 客户端请求使用 TLS。Debug 构建仅为开发机上的 Firebase Emulator Suite 覆盖允许 HTTP，Debug APK 不作为正式分发包。

Room 不具备应用层端到端加密；本轮依赖 Android 应用沙箱、设备文件加密、设备锁和关闭系统备份，未冒险加入 SQLCipher。若未来引入数据库加密，必须先定义可恢复密钥生命周期并验证无损迁移。

## 离线、冲突与删除

- 本地修改先写 Room 并标记 `PENDING`；联网、应用启动、手动同步或 WorkManager 重试时上传。
- 远端快照不能覆盖尚未确认的本地版本；迟到的上传确认也不能把新编辑标成已同步。
- 两台设备编辑同一天时，在同一云端记录 `id` 代际内使用各自最后确认的 `remoteRevision` 作为并发基线；云端修订已前进时保留服务器版本，不依赖可能不准确的设备系统时间。若文档物理消失后被重建，新的 `id` 标记新的代际，即使修订号从 1 重新开始，其他设备也会接受并收敛到新代际。
- 清除记录写入墓碑，防止另一台长期离线设备把旧记录恢复出来。
- WorkManager 使用串接后续任务的策略；运行中的同步不会吞掉其间新产生记录的下一次调度。
- 云端快照逐条校验；单条格式异常只标记为数据错误，其余正常日期继续下载和上传。
- Firestore 实时监听遇到瞬时错误会指数退避并自动重新订阅；离线期间等待有效网络，不进行无意义重试。
- 登录后的本机记录迁入只依赖 Room，不等待 Firestore；服务器监听恢复且仍有 `PENDING` 数据时会立即触发补偿同步，即使系统网络状态没有变化。
- 同步失败只显示经过净化的错误，不在日志或 UI 暴露文档内容。
- 网络、认证、权限、配额、服务、数据和未知错误分别提供对应操作；只有网络类错误提示检查 VPN。记录始终保留在 Room，提示不会阻塞继续记录、查看日历或统计。
- 当前版本不接入分析或崩溃上报 SDK，不自动上传日志、错误堆栈、设备信息或使用行为；用户可按隐私说明通过 GitHub Issue 主动反馈问题。
- 面向使用者的完整保留、删除、第三方和反馈说明见仓库根目录 [`PRIVACY.md`](../PRIVACY.md)。

## 逐次详情同步

- 手冲详情继续写入 `/users/{uid}/handBrewRecords/{YYYY-MM-DD}` 的模块专用 `details` 数组；做爱详情只写入对应的 `sexRecords` 文档，不跨模块合并。
- 本地 Room 先在同一事务提交聚合次数和详情，详情变更沿用聚合行的 `updated_at`/`remote_revision` 进入 `PENDING` 队列；云端不可达时详情仍保留在本机。
- 远端快照只有在本地聚合不处于 `PENDING` 时才替换详情；逐条解析异常只拒绝当前日期文档，不关闭其他日期的同步流。
- 详情感受不写入日志、诊断摘要、统计指标或错误文案；账号删除和本机数据删除会清理两套详情表与各自云端路径。

## 账号与云数据删除

- 从“账号与云同步”进入，先展示不可撤销警告和本机数据选择，再要求输入当前密码完成第二次确认。
- 默认选择“保留在本机”：认证账号删除成功后，非墓碑记录转入 `__local__`，继续作为离线记录使用。
- 用户也可明确选择“同时删除本机记录”；该选择不会被预选。
- 执行顺序固定为密码重新认证、分批删除本人各模块 Firestore 集合、准备各模块的可选本机恢复副本、删除 Firebase Authentication 账号、清理各模块账号缓存。当前列表包含手冲和做爱；聚合器会逐个尝试全部模块，并保留首个失败及后续受抑制异常，避免一个模块失败后静默跳过其他模块。
- 密码错误、断网、VPN 未连接或云端删除中途失败时，不删除认证账号或本机缓存；可在网络恢复后重试。云端已清空但认证删除结果未知时，应用不会把该状态当作普通失败来重新同步，保留按账号隔离的恢复副本并暂停该账号同步；启动时会重新确认 Auth 状态，只有明确确认账号不存在后才清理账号缓存。若确认账号仍存在，则丢弃该账号恢复副本、重新标记本机记录待同步并恢复同步；Auth 明确删除后才把恢复副本 promote 到 `__local__`，promote 前如果发现已有本机记录会安全阻断并提供重试入口，避免覆盖用户已有的本机数据。
- 应用不记录删除时输入的密码；删除操作不读取其他账号路径。

## 设备备份

Manifest 保持 `android:allowBackup="false"`，系统云备份和系统设备迁移不会复制数据库。跨设备恢复只通过用户主动登录同一账号完成。未登录且从未同步的本机记录在卸载或清除应用数据后无法恢复。

Room 数据库当前没有应用层端到端加密，也没有使用 SQLCipher；静态数据依赖 Android 应用沙箱、系统文件级加密和用户设备锁保护。已解锁且被提权、Root 或恶意调试控制的设备不在当前保护边界内。若未来引入应用层数据库加密，必须先设计可恢复的密钥生命周期和无损迁移，不能直接替换数据库导致现有记录丢失。

## 持续隐私门槛

- 持续提供可访问的隐私政策与账号/云数据删除入口。
- 当前 GitHub 侧载阶段不接入或强制 App Check；未来具备 Play Console/可验证侧载配置后，必须先观察模式验证再决定是否强制。
- 复核 Firebase 数据保留、支持邮箱、滥用配额与告警。
- 禁止提交真实数据库、账号口令、服务账号、签名文件或 `google-services.json`。
